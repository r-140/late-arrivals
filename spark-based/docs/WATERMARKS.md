# Watermarks and late arrivals
## Do not confuse four concepts
| Concept | Meaning in this lab |
| --- | --- |
| Business time | data.event_time of an order; can be seven days old when inserted today |
| Source modification time | source_time generated by the PostgreSQL trigger; assigned before commit and before extraction |
| Extraction checkpoint | Durable change_queue.batch_no membership; independent of event time and source clock |
| Spark streaming watermark | Event-time bound for state eviction/late-data handling in Structured Streaming; absent from this batch project |

`updated_at` is not forbidden because of its name. It is unsafe as the only lower-bound extraction filter if it tracks business time, is backdated/non-monotonic, misses deletes, is assigned before a delayed commit, or hides intermediate changes. An overlap plus dedup helps within a bounded lateness guarantee, not arbitrary delayed commits.

Even a trigger sequence is not global commit order. Transaction A reserves ID 10 and stays open, transaction B reserves 11 and commits first. Advancing max ID to 11 would skip A after it commits. This implementation claims every visible unassigned event; 10 remains unassigned and enters a later batch.

`updated_at` on a real dimension can describe audit time while effective_from describes business validity. A retroactive SCD2 correction needs both and triggers re-linking previously loaded facts.

Delta transaction versions are storage commit IDs used to pin output snapshots; they do not replace source extraction checkpoints. ClickHouse batch publication is a separate load acknowledgment.
